### INTRO/Dragon test

==Hi, today I'm going to go in depth into how I've been making my own game engine and the code I wrote to do it. You wont need any knowledge in computer programming to follow along in this video or if you want you can follow along and follow my steps to make your own game engine, however please note I'm not going to go over everything this is not a tutorial. The first thing I worked towards is drawing a model on the screen, to do this you need shaders and a mesh.==  A mesh is a collection of vertices, edges and triangles and a Shader is a program that runs on the GPU. The Shaders we will write come in two forms, a vertex shader and a fragment shader, which I'll be calling a pixel shader for simplicity. The vertex shader turns a models 3D vertices into 2D pixel positions, we do this by multiplying the projection matrix and the model matrix by the vertices position. The projection matrix is *how* we want the 3D position to be converted to 2D screen positions, and OpenGL kindly gives us an easy function for this. The model matrix is simply a list of transformations we want to apply to the model, such as position, rotation and scale. Now our computer knows where to draw the triangle, we just have to tell it how to draw the triangle. To do this lets write the pixel shader. OpenGL expects a pixel shader to output the pixel colour in the RGBA format and it will run our shader code for every single pixel. For now we will output a flat white colour. After writing a simple model loader we have our first model on screen. If you're older than 2 and blessed with vision you may notice that the model is a dragon. This dragon is a famous testing model in graphics programming and im using it simply as a test because it has a high poly count. lets make another test with 10 dragons, each dragon has two hundered thousand triangles so thats a total of 2 million, this is a huge hit to performance and its not for the reasons you might think. The common gpu can handle millions of triangles easily the real problem here is memory, the Engine loads in this huge dragon model 10 times into gpu memory, which is a huge waste. We need to somehow check if the dragon model is loaded already and, if it isnt then the Engine should load it into memory but if it is just get a reference to the model already in memory. The solution to this problem is fairly simple all we need to do is make an asset manager. Instead of each Mesh object loading in a model it will ask the asset manager for model data, and asset manager will look in its big list of loaded in assets and give it to model if it can find it and if it cant it loads the model in, adds it to its big list of assets and returns the model data to the mesh object. This saves us alot of memory and gives a huge boost in performance. So i think its time for another test, this time lets make the engine load in.. idk..... a square of 50 by 50 dragons? The Engine runs beautifully even with 2500 dragons, rendering 500 million triangles at a smooth 15fps is great especially because no game will ever have close to that number of tris.
